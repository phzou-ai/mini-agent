# Historical Evidence

This directory preserves completed plans, dated assessments, and maintenance
records that still explain the current system. Historical documents are
evidence, not current architecture or authorization for new work.

## Domains

1. [runtime/README.md](runtime/README.md) - completed runtime milestones, dated
   architecture assessments, and refactor evidence.
2. [maintenance/README.md](maintenance/README.md) - completed cleanup and code
   organization records plus evidence-based triggers for a future pass.

## Reading Rule

Read the applicable Stable Reference first, then use history to understand why
the current boundary exists:

- [Current System Architecture](../architecture/current-system.md)
- [Lifecycle And State Ownership](../architecture/lifecycle-and-state.md)
- [Backend Runtime Contracts](../components/backend/runtime/README.md)
- [Active Development](../dev/README.md)

Do not copy historical status or next-step language into a current plan. If a
historical concern becomes active again, create or update one authoritative
roadmap under `docs/dev/` with current evidence and acceptance criteria.
